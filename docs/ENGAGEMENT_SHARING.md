# Optional exploration and sharing

The public result page builds these features from `quiz-summary-3` and the existing affinity and clarification projections. Version 3 keeps an inherited rule scope separate from an explicit proposition; historical version-2 projections retain their old field semantics. `packages/experience/engagement.js` imports no interpretation, response, or routing engine. The share builder accepts interpreted summary data and a narrow allowlisted administration-version object; it rejects a full response-bearing quiz object. Activity in `packages/experience/exploration.js` version `exploration-2` is stored under a separate local-storage key. Neither activity nor a share snapshot enters worldview interpretation, route selection, or affinity evaluation.

## Explore

The result page records domains, traditions, and source trails the user voluntarily opens after completion. Milestones describe activity only: opening all domains, opening a source, inspecting two traditions, inspecting an open question, or completing multiple route depths. They award no points and depend on no belief, answer direction, timing, certainty, or consistency. If local storage is unavailable, the result still works and the activity record may not persist.

Deepening actions use the existing `planWorldviewFollowups` output. The displayed count is the number of current planner entries, and each action has a reason tied to mixed, weak, insufficient, or unmeasured interpreted evidence. A user can stop at the chosen depth. Clarification and route continuation preserve compatible answers through the existing administration state; this layer does not select questions itself.

Reading trails reference the interpretation or affinity source list, nearby views, and non-entailments. They are invitations to read contrasting philosophy, not assertions that the respondent belongs to a school. Two-tradition comparison displays source-backed defining doctrine, current evidence findings, and non-entailments independently. There is no distance, winner, rank, or match percentage.

## Share

The four formats are **overview**, **domain**, **affinity**, and **exploration**. Overview requires an explicit selection of one to four directional answer patterns under the authored rules; a row can have an exact proposition or a visibly marked inherited scope. Domain shows up to six interpreted rows from one domain. Rows retain their direct or derived status. A frozen derived engine state is not newly shareable when its prerequisites lack an exact public proposition or its rule and prerequisites lack rule-linked supporting source claims; the result page keeps such a row visibly awaiting model review. Affinity shows defining criteria, including unmeasured doctrine and non-entailments. Exploration shows activity counts. Every format carries an exploratory qualification, source-result uncertainty counts, exact model and instrument versions, route/form policy, affinity catalog version where present, creation time, and an opaque snapshot ID. No raw answer, session ID, research-consent record, withdrawal token, account data, or generic analytics identifier is projected.

New `worldview-share-5` snapshots keep `proposition` null when a historical public rule stored only a broad `scope`; `propositionBasis` and `scope` carry that distinction into overview, domain, affinity, text, SVG, and historical comparison views. Direct result status copy now states when the frozen rule has only an inherited scope or when its exact proposition lacks a rule-linked supporting source claim. That copy and its explanation are frozen into new share snapshots; older snapshot files retain their original wording. Affinity criteria likewise keep `mappedProposition` separate from `mappedScope` and retain the linked interpreted state. Shared text qualifies scope-derived overlap and describes partial mappings as unresolved doctrine even when the linked state is opposed or supported. Historical `worldview-share-1` through `worldview-share-4` files retain their original fields and remain readable; opening them does not add evidence claims that were absent from those snapshots.

`worldview-share-6` keeps each selected result's source ID, locator, rule-linked claim text and relationship (`supports`, `context`, or `challenges`), broader source-record claim when present, and topic-only status. Text and SVG cards disclose the counts of these roles; the local JSON viewer exposes their exact wording under “Inspect sources.” A citation with only topic or source-record context is never presented as direct support for the result. Older version-5 snapshots remain readable with their original title-and-URL citations; the viewer states that their claim-level roles were not retained. These are provenance disclosures, not validation of the philosophical rule or questionnaire.

The frozen affinity engine's `summaryState` remains reproducible under catalog 1.0.0. The `quiz-summary-3` presentation adds a separate `affinityPresentation` qualification: a tradition with any defining direct or partial criterion mapped only to an inherited rule scope displays `legacy_scope_unresolved`; one with an explicit mapped proposition but no rule-linked supporting source claim displays `source_claim_unresolved`. Neither can satisfy the respondent-facing “established affinity” indicator. All six first-catalog traditions currently have scope-only defining mappings. Version-5 cards retain the authored `summaryState` for historical context and display the qualification. A claim link is a metadata requirement, not proof of scholarly adequacy or empirical validity. This is a conservative presentation of the existing evidence, not a new doctrinal finding or a silent edit of the catalog.

The user can copy exact text or download a JSON or SVG snapshot. The static `/apps/quiz/share.html` viewer opens a saved JSON file locally and presents an accessible text equivalent with source links. It can compare two selected snapshots. When interpretation versions differ, it declines to call a status difference respondent change. Even under one model, an apparent change could result from more questions, changed answers, or both. The viewer does not upload files. JSON files remain interpretable after the current model changes because they contain the selected historical statements and version context; the app never recomputes them on open. A downloaded file can be edited by its holder and is not cryptographically authenticated.

There are no public share URLs, hosted cards, social previews, usernames, or automatic publication in this release. Thus public-link revocation and metadata previews do not apply. A recipient who has a copied file or text can retain it; the app cannot retract their copy. The existing local quiz holds one active administration, so cross-administration comparison requires the user to retain two snapshot files. The viewer does not claim to distinguish deeper-route evidence from a changed belief.

## Analytics and checks

When first-party product metrics are enabled, optional events cover exploration, reading, source opening, tradition comparison, and share export. Each event carries only route ID, completed item count and an optional domain ID. The event endpoint rejects raw answers and arbitrary fields. No metrics are sent when disabled, and metrics do not modify inference.

`npm run test:engagement` covers evidence projections, privacy, uncertainty, versions, source trails, comparison, activity isolation and recommendation reasoning. `npm run test:quiz:browser` exercises actual Chromium controls, downloaded snapshots, the file viewer, accessibility and narrow mobile layouts with synthetic answers. These are software checks, not psychometric evidence or user research.
