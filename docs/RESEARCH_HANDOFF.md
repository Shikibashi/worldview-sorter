# Independent research handoff status and release procedure

The research collector is optional and disabled by default. This repository checkout has no mounted production contribution store or configured production research path. On 2026-09-29, **actual consented administration, pseudonym, completion, locale, version, item, and repeat counts were not verifiable here**. A missing local store must not be described as zero production participation. No production incident, recruitment, retention, or test-record register is present in this repository. An operator with access must run the private inventory and review those records before assessing readiness or releasing data.

## Source-data boundary

The current consented endpoint accepts an explicitly affirmed frozen 238-item Full pilot attempt under `research-consent-1.0.0`. It can include completed or started pilot attempts. Quick, Standard, Deep/adaptive stages, and nonconsenting ordinary browser sessions are not in this store. There are no accounts or demographic fields. Consent is per contribution, may occur after the answering session, and is not retroactively inferred for other sessions. Withdrawal replaces an active record with a response-free tombstone. Optional browser-held linkage permits some repeated administrations; lost/declined linkage means repeat users cannot be reliably recognized. `contributedDate` is the UTC submission date, not answer time. The store has no automatic expiry; the operator must enforce retention and backup deletion.

The normalized export distinguishes answered, `no_view`, `not_understood`, `not_applicable`, `branch_not_shown`, and `not_reached`. Items absent from the Full pilot are missing by instrument design and have no row. Invalid API submissions are rejected, not exported as an `invalid` response. Technical presentation failure has no separate row code. The collector omits exact response times, geographic and demographic data, recruitment source, and a bot marker. These absences constrain analysis; do not manufacture flags from answer content.

The current collector and extractor restrict client-provided respondent locale and item wording metadata to the pinned English values. An older active record with an arbitrary locale, text-version, or variant string blocks export for operator review rather than carrying possible private text into the researcher package. The current extraction logic is `research-snapshot-extractor-1.3.3`; the row format remains `research-package-1.1.0`.

## Operator sequence

1. Confirm the actual private store, consent terms, retention policy, incident/test logs, withdrawal obligations, and recipient access owner. Run `npm run research:inventory -- --store /private/contributions --out /private/inventory.json` for the whole store, then run it with paired `--from YYYY-MM-DD --through YYYY-MM-DD` for the planned snapshot window. Review private diagnostics, including item exposure and category sparsity, without putting rows in tickets or logs.
   The inventory applies the same frozen-pilot eligibility check to the **selected window**. `eligibilityCompatibleAdministrations` counts individually compatible records; `snapshotExportableAdministrations` is zero if any selected active record is incompatible. `sourceStatusCounts` covers the whole store, while `contributionDateWindow` identifies a selection; withdrawn tombstones cannot be assigned to a contribution-date window after their original response data were removed. Inspect `unsupportedReasons` in the private detailed report before extraction. An incompatible record strictly outside a dated window does not block that snapshot; one inside it does. Do not remove incompatible historical records merely to make an export pass; add an explicit versioned export path for the affected cohort.
2. Decide a contribution-date window and document known non-human/test/incident exclusions in a private mode-0600 JSON file. Do not infer malicious participation from a philosophical position. Review active, withdrawn, and unsupported-consent counts. If the store contains a version the exporter cannot reconstruct, add a versioned export path; do not coerce it to the current pilot.
3. Quiesce writes or take a consistent restored copy of the store. Run `npm run research:snapshot -- --store … --out … --id … --from … --through … --quiesced [--exclusions …]`. Verify the new directory with its included `node verify_snapshot.mjs .`, Python loader, and, where available, R loader. Check the file-hash manifest against the intended release copy.
4. Record the snapshot ID, manifest hash, extraction window, exclusions, consent rule, schema, release date, model tuple, access steward, recipients, and any correction link in an operator-controlled release register. Do not silently replace a cited package. An external archival DOI may be added later; none is fabricated here.
   New packages use `research-snapshot-1.3.0` with extraction logic `1.3.3`; its authored layer includes compact item/revision/meaning traces, a reproducible claim/source/affinity index, and a distinction between explicit propositions and legacy scope labels. Diagnostics include rule-linked exact item-pair exposure and linked-repeat date/overlap summaries; the included verifier replays them and checks row schemas plus pinned consent, model, route, catalog, and wording relationships. Keep any prior package and its included verifier unchanged. A corrected package receives a new snapshot ID.
   Snapshot publication also creates a mode-0600 `release-linkage-<snapshot ID>.json` in the **private contribution store**, outside the researcher package. It maps contribution receipts to that release's rekeyed administration IDs and pins the released manifest hash. Back it up with the contribution store, restrict access to release stewards, and retain it while downstream copies may require withdrawal notices. A withdrawal tombstone retains its contribution ID; use that ID to identify affected released rows, notify recipients under their data-use terms, and issue a new snapshot ID for corrections. Neither withdrawal nor a corrected release can retract an already distributed copy automatically. Never transfer the private linkage file with a researcher package.
   After withdrawal, run `npm run research:withdrawal-impact -- --store /private/contributions --contribution UUID` on the private host to list affected snapshot IDs, released administration IDs, and manifest hashes. An empty list only covers releases that have retained linkage files; it cannot prove that no older or externally created package included the contribution. Keep the release register and recipient list for the actual notice.
5. Keep row-level release **restricted by default**. Approve specific researchers and uses, security/retention and onward-sharing terms, withdrawal notices, and incident handling before transfer. Public aggregate documentation can be separate. Name a real access contact before external release. Use the repository issue tracker for schema or model criticism without attaching respondent data; route substantive philosophical changes through the editorial proposal workflow.

## Structural feasibility pending real counts

`readiness.json` provides per-snapshot classifications with reasons. With no accessible production store, item distributions, dimensional exploration, local dependence, reliability, linked test–retest, and authored-rule critique are **not yet assessed empirically**. Route comparison is **impossible with current consented collection**, because only Full pilot contributions are accepted. Demographic DIF is **impossible** because demographics are not collected. Cross-language analysis is **impossible with current eligible English-only collection**; draft bundles do not create observed language groups. Measurement invariance requires actual compatible comparison groups and joint-item coverage. An operator's record count alone cannot change these structural conclusions or establish validity.

The handoff can test whether rows and manifests are complete and replay authored outputs. It cannot choose a factor structure, estimate reliability or invariance, declare rule accuracy, infer population prevalence, or convert affinity satisfaction into a validation criterion. Future researchers must specify those analyses and their assumptions independently.

The historical `model-release-1.0.0` manifest pins philosophical data but not executable inference code. Active release `1.1.0` pins an `engine_source` archive. A snapshot compares extraction-time inference modules with every included administration's pinned archive: it records a positive code-equality claim only when all match, and otherwise records that historical code equality is unproven. Research-curation code remains extraction-time code. Successful replay tests technical completeness, not scientific validity. Snapshot packaging keeps observed answers separate from authored replay.
