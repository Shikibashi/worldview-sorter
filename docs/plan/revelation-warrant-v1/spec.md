# Revelation warrant correction

## Context Map

Existing item bank and released routes → exact item-revision responses → EP10 public rule → evidence-qualified result and scoped reference comparison. The static public app keeps answers locally. Old release manifests and engine sources remain immutable.

## Problem Statement

The active EP10 rule uses `EPI021@1` (unspecified audience) and `EPI032@1` (explicit experiencer). Its broad wording and current answer mapping can make a result seem to assert more than the two answers establish. `EPI032`'s `some` answer acknowledges initial justification while requiring further support, but the current rule treats it as nondirectional. The unreleased `EPI120@1` draft combines strength and outsider warrant in answer options.

## Requirements

1. State one exact respondent proposition and keep first-person initial warrant distinct from substantial warrant and outsider/public warrant.
2. Use only answer meanings that directly bear on that proposition. Preserve mixed, missing, skipped, and route-omitted behavior.
3. Retain old item, rule, routes, catalog, and result behavior under historical releases.
4. Add only a necessary discriminator, and only after source and semantic review. Keep unrelated draft items unreleased.
5. Update source-to-claim records, release manifests, affected route/coverage/affinity bindings, tests, and current-facing documentation as required.
6. Preserve static local-first privacy, no identity match or percentage, and existing accessibility behavior.

## Non-goals

No claim that a revelation is true, that outsiders should accept it, that it grants religious or civic authority, or that authored questions are psychometrically validated. No new backend or Docker production deployment.
