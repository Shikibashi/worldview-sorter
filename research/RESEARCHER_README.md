# Worldview Sorter research snapshot

This directory is a frozen, restricted research handoff. Read `snapshot.json` for its identifier, extraction date, consent rule, contribution-date window, exclusions, and included versions. `manifest.json` hashes every other file. Cite the snapshot ID and manifest hash; no DOI has been assigned. A correction requires a new snapshot ID and directory.

## What these observations are

Worldview Sorter is an optional philosophical questionnaire. Respondents choose a route and may stop, return, or explore further. The **research contribution API currently accepts only the frozen Full pilot**, with explicit consent for that attempt. Therefore this dataset cannot represent all Quick, Standard, adaptive, or nonconsenting users. It is a self-selected application-user sample. Recruitment source is not recorded; route selection outside the eligible pilot and nonconsent cannot be reconstructed from this package. No account or demographic fields are collected. The contribution date is the UTC date of consented submission, not the time of answering.

`responses.ndjson` is the observed layer. Each assigned pilot position has a row, including branch exclusions and unreached positions. `rawValue` is an answer, never a construct score. `administrations.ndjson` and `respondents.ndjson` hold snapshot-specific pseudonyms. Optional browser-held linkage permits some repeats; an unlinked pseudonym does **not** certify a unique human. `items.ndjson`, `item-codebook.ndjson`, and the frozen JSON files define exact question revisions and authored targets. `authored-claim-index.json` is a generated, reproducible view of direct and derived rules, answer mappings, route inclusion, source-link status, and affinity uses; it contains no respondent rows. Unapproved localization bundles may be present as historical references; only the bundle pinned by an administration describes wording used. A null bundle on older records means canonical English wording was not pinned per item.

`derived.ndjson` is a **separate authored replay** of public propositions, derived propositions, and doctrinal affinities. These outputs are theoretical rules applied to answers, not observed traits, verified identities, or criterion labels. Researchers can ignore the file and work directly from responses. `verify_snapshot.mjs` checks that the released raw rows and copied extraction-time engine reproduce this authored layer. It also cross-checks consent terms, exact wording, model and route versions, affinity catalog, codebook, diagnostics, and localization metadata against their released pins. `snapshot.engineReplay.historicalSourceEquality` states whether every included administration's release pins inference modules matching that replay; older release 1.0.0 does not. This is a technical completeness check, not scientific validation.

In snapshot schema 1.3.0, `proposition` is null for historical rules that stored only a broad `scope` label. `propositionBasis` marks those rows `inherited_rule_scope`; the label is retained separately for historical interpretation. It must not be treated as an independently reviewed exact proposition. The same distinction appears in the item and authored-claim indexes. A claim marked `topic_only` has no exact source claim attached; `source_record_claim` is broader contextual metadata; neither should be mistaken for rule-level scholarly review.

The frozen affinity catalog maps 16 of its 18 direct or partial doctrinal criteria to these scope-only rules. Treat its criterion findings as authored comparisons to be examined, not criterion truth. `authored-claim-index.json` identifies each tradition, criterion, rule, answer mapping, and source-link status within this package; researchers can ignore affinities and analyze raw answers independently.

`quality-flags.ndjson` contains only mechanical metadata flags such as partial administration, unreached positions, branch exclusions, optional linked repeats, and historically unpinned wording. It is not an automated judgment about sincerity, ideology, or whether a respondent is human. Known test or incident records are excluded only through the reviewed private extraction list recorded in aggregate in `snapshot.json`.

`diagnostics.json` gives aggregate item distributions, substantive answer burden, exact-revision co-answer counts for pairs linked by public authored rules, and linked-repeat contribution-date gaps and shared exact-revision counts. Same-day repeat order and actual answer intervals are unknown; linkage is optional and repeats outside the window are absent. These summaries screen exposure, not local dependence, stability, independent evidence, or a validated construct. The included verifier recomputes diagnostics and readiness from the released raw rows and copied diagnostic code. It also rebuilds the item codebook from the released bank, registry, interpretation rules, scales, and localization bundles.

## Load and verify

From this directory run `node verify_snapshot.mjs .`, `python3 load_snapshot.py .`, or `Rscript load_snapshot.R .` (R requires `jsonlite`). All data tables are NDJSON and can also be streamed by standard JSON tools. The legacy `data-dictionary.md` documents the normalized response tables and answer codes. `snapshot-dictionary.md` documents the added release, codebook, diagnostics, and authored fields. `response-scales.json` gives scale meanings; item-specific options are in `items.ndjson`. `model-release-*.json` and the copied model, route, bank, registry, localization, source, and affinity files preserve the historical authored configuration. The `engine/` directory is a byte-for-byte source snapshot needed only for technical replay.

## Consent, access, and limitations

The source exporter includes active records with per-attempt consent and excludes withdrawal tombstones at extraction. The package records the extraction rule and aggregate store statuses, but rekeyed rows cannot independently prove the private consent history to a recipient; that remains an operator attestation and release-audit responsibility. A withdrawal after release cannot automatically retract a copy already supplied to a researcher. The operator retains a restricted contribution-receipt-to-released-administration linkage outside this package, allowing affected rows to be identified for a withdrawal notice or corrected release. Recipients do not receive that linkage. Release stewards must review the source store before further distribution. This package is **restricted by default** because philosophical answers and longitudinal combinations can remain recognizable after pseudonymization. Do not publish row-level files merely because direct identifiers are absent. Grant access only through an operator-approved request and data-use terms covering purpose, security, onward sharing, retention, withdrawal notices, and incident response. No formal access contact is configured in this repository; the operator must name one before external transfer.

The [Standards for Educational and Psychological Testing](https://www.apa.org/science/programs/testing/standards) concern evidence for particular test interpretations and uses; this release supplies observations and hypotheses, not that evidence. [AAPOR's nonprobability-sampling guidance](https://aapor.org/publications-resources/reports/) is relevant to the self-selected application sample. Read `ANALYSIS.md` and `WARNINGS.md` before interpreting results.

Report schema and reproducibility problems through the project's issue tracker without attaching respondent rows. Philosophical-model criticism should link to an editorial proposal under the repository's governance process. Distinguish maintainer, commissioned, and independent analyses in any later publication; access to this package does not make an analysis independent.
