# Snapshot 1.3.0 extension dictionary

The included `data-dictionary.md` is the authoritative field dictionary for `respondents.ndjson`, `administrations.ndjson`, `responses.ndjson`, `items.ndjson`, and `versions.json`. Those are normalized **observed** tables except `items`, `versions`, and model files, which are authored reference data. This extension documents every added field. `null` always has the documented meaning; it is never a neutral answer. All identifiers in released rows are newly randomized for this snapshot.

| `snapshot.schemaVersion` | `research-snapshot-1.3.0` | Required release format; public metadata. Version 1.3 adds a generated authored-claim index. Prior packages keep their included verifier and dictionary. |

| `snapshot.extractedAt` | ISO timestamp | Extraction time, not response time. |
| `snapshot.extractionLogicVersion` | `research-snapshot-extractor-1.3.3` | Version of the curated extraction algorithm. Version 1.3.3 checks inference-code equality against each included administration's pinned engine archive; 1.3.2 added row-schema verification; 1.3.1 added private release linkage; 1.3.0 added the authored-claim index. |
| `snapshot.supersedes`, `correctionNote` | prior snapshot ID or null; text or null | A correction's predecessor and rationale; both null for an initial release. |
| `snapshot.contributionDateWindow` | `{from,through}` ISO dates | Inclusive UTC consented-contribution window. |
| `snapshot.sourcePackageSchemaVersion` | string | Normalized source export format. |
| `snapshot.consentRule` | string | Exact eligibility policy; per-attempt affirmative consent and active status. |
| `snapshot.includedAdministrationCount` | integer | Number of included active administrations. |
| `snapshot.excludedCounts` | reason → integer | Outside-window and reviewed private exclusion counts; no source IDs. |

| `snapshot.botAndIncidentReview` | string | Limits of known-record review. |

Research-curation code remains extraction-time code in all cases. |

| `directRules[].affinityUses[]` | `{traditionId,criterionId,role,doctrine,mappingStatus,expectedState,criterionSourceIds}` | Catalog criteria that map to this rule. Doctrinal comparison is authored affinity, never respondent identity. |

| `derived.researchAdministrationId` | snapshot-specific `a-…` | Join to one administration; no raw answer values in this file. |
| `derived.modelVersion`, `resultSemanticsVersion`, `affinityCatalogVersion` | strings | Exact authored replay versions. |
| `derived.propositions[]` | `{id,domainId,constructId,proposition,scope,propositionBasis,state,leanDirection,supportingUnits,opposingUnits,measurementStatus,evidence,sourceIds}` | Public direct-rule outputs. `proposition` is null when the historical rule stored only a `scope` label; `propositionBasis` makes that distinction explicit. `evidence` contains `{itemId,itemRevision,unitId,meaning}` for response records considered by the authored rule; it omits raw answer values, which remain in `responses.ndjson`. `sourceIds` resolve through the frozen model. Authored, not observed. |
| `derived.derived[]` | `{id,proposition,state,dependencies,directConflictItemRefs,sourceIds}` | Derived proposition outputs, required direct states, conflict item/revision references, and source links. A conflict reference does not duplicate the raw answer value. |
| `derived.affinities[]` | `{traditionId,summaryState,criteria}` | Doctrinal comparison, not identity or ranking. Criteria contain `{criterionId,role,mappingStatus,mappedPropositionId,finding,observedState,sourceIds}`; null mapping ID means doctrine has no mapped proposition. `observedState` is an interpreted state, not a raw observation. |
| `quality-flags.researchAdministrationId` | snapshot-specific `a-…` | Join to an administration; flags are derived mechanically from released metadata, not an exclusion decision. |
| `quality-flags.flags` | string array | Any of `partial_administration`, `unreached_positions`, `branch_exclusions`, `linked_repeat`, `historical_wording_unpinned`, `model_release_unpinned`. Empty means none of these six flags; it does not certify response quality or humanity. |

## Added categorical encodings

- `derived.propositions[].state` and `derived.derived[].state`: `supported`, `leaned_toward` (direct only), `mixed_context_dependent`, `opposed`, `insufficient_evidence`, or `not_measured`. `leanDirection` is `support`, `oppose`, or null; null means no directional lean.
- `derived.propositions[].measurementStatus`: `measured_content` or `not_measured_content`. Authored content availability is separate from whether a respondent supplied enough evidence.
- `derived.propositions[].evidence[].meaning`: `support`, `oppose`, `neutral`, `qualified_or_non_directional`, or an explicit special response state such as `no_view`. The item revision and evidence unit identify the authored mapping. Absence from this array means no response record for that rule item; join the raw table and model to examine route absence and missingness.
- `derived.affinities[].criteria[].mappingStatus`: `direct`, `derived`, `partial`, `not_measured`, or `unsuitable`; `role`: `defining`, `characteristic`, or `disputed`. These are catalog judgments, not measured respondent traits.
- `derived.affinities[].summaryState`: `material_divergence`, `no_sufficiently_established_affinity`, `overlap_with_unmeasured_core`, `overlap_with_unresolved_core`, or `overlap_on_measured_core`. No state means identity or a calibrated probability.
- `derived.affinities[].criteria[].finding`: `overlap`, `divergence`, `unresolved`, `contradictory`, `partial`, or `unmeasured`; `observedState` is one of the interpreted proposition states above or null when the doctrinal criterion is not mapped.
- `item-codebook.targets[].relation`: `positive`, `negative`, `diagnostic`, or `tradeoff`; `role`: `primary` or `secondary`. These are authored target tags, not statistical loadings.
- `item-codebook.localizedRealizations[].status`: `approved` or `untranslated` in this release. An untranslated bundle has no respondent-facing item realization. `item-codebook.status` is currently `candidate`, meaning authored content, not a validated scale item.
- `item-codebook.authoredRuleUses[].use`: `public_direct`, `research_only`, or `other_authored`. Source records and rule definitions are preserved in the frozen files; the codebook does not turn a research-only rule into a respondent result.
- `diagnostics.routeVersions` joins instrument and form-policy versions with ` / `; `localeVersions` joins locale and bundle version with ` / `; `itemRevisions` joins item ID and revision with `@`. These are display keys for aggregate counts, not extra observed variables.

The repository's `research-export.schema.json`, copied into the package, gives exact normalized field names and categorical enums. `verify_snapshot.mjs` checks hashes, row references, response codes, consent/version pins, and replay. The package contains no demographic variable, session identifier, IP address, account identifier, support text, or exact answer timestamp. `recordedResponses` counts special-state responses as well as substantive answers.

The operator-only `release-linkage-<snapshot ID>.json` is stored beside private contributions and **is not an exported field or package file**. Its `research-release-linkage-1` schema has `snapshotId`, `snapshotManifestSha256`, `createdAt`, and `mappings[]` of private `contributionId` to released `researchAdministrationId`. It exists solely to locate affected released rows after consent withdrawal and must never be supplied to researchers.
